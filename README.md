# CCOT / RRT Program Dashboard

R Shiny dashboard for a pediatric **Critical Care Outreach Team (CCOT) /
Rapid Response Team (RRT)** program. Supports operational monitoring, QI
reporting, and implementation-science evaluation of a proactive PICU
MD + RN rounding service on floor patients at risk for deterioration.

The app loads simulated data out of the box. To go live, replace the
simulator with pulls from your warehouse — every dataframe contract is
documented below.

---

## Analytic conventions

| Concept | Definition |
|---|---|
| **T0 (CCOT)** | `first_assessment_datetime` per encounter (first CCOT assessment only) |
| **T0 (RRT)** | `activation_datetime` from `rrt_fact` |
| **Observation window** | 72 hours from T0; controlled by `OBSERVATION_WINDOW_HOURS` in `global.R` |
| **Emergency transfer** | PICU transfer with intubation **OR** vasopressor initiation, within the 72h window |
| **Time-of-day windows** | `00–07` Night, `07–15` Day, `15–23` Evening, `23–00` Late (`SHIFT_BUCKETS` in `global.R`) |
| **Day of week** | Mon-first ordered factor |
| **Join key** | `pat_enc_csn` (Epic CSN) across all tables; `charges` additionally joins on date |

The canonical analytic frames `ccot_cases`, `ccot_outcomes`, and
`rrt_cases` are built once in `global.R` and reused by every module.

## Required dataframes

Every dataframe below is currently generated by
`data/simulate_data.R`. The schema is what each module consumes; column
**names and types matter**, ordering does not. Replace the simulator
block-by-block (the file has inline comments marking each real-source
injection point).

### 1. `encounters` — base patient/encounter spine
**Source:** Epic Clarity `HSP_ACCOUNT` / `PAT_ENC_HSP`, one row per
inpatient encounter.

| Column | Type | Notes |
|---|---|---|
| `pat_enc_csn` | chr | Primary join key |
| `patient_id` | chr | MRN |
| `encounter_id` | chr | Epic encounter ID |
| `unit` | chr | Floor unit name; must match `FLOOR_UNITS` in `global.R` |
| `age_years` | num | Patient age at admission |
| `admit_datetime` | POSIXct | Inpatient admit timestamp |
| `is_watcher` | lgl | Was this encounter ever on the CCOT watcher list? |
| `watcher_flagged_datetime` | POSIXct | When the encounter was first flagged (NA if never) |

`is_watcher` is the first node in the Overview Sankey pipeline. Real
source is the CCOT watcher list itself — typically a manually
maintained at-risk list in Epic (custom flowsheet, registry, or
care-team SmartList). If your site stores watcher status as a
longitudinal event log instead of a boolean, summarize to one row per
encounter with `is_watcher = any(flagged)`.

**Used by:** all tabs (via `ccot_cases` / `rrt_cases`); Overview Sankey
uses `is_watcher` directly.

---

### 2. `ccot_assessments` — parsed CCOT notes
**Source:** produced by `etl_ccot_notes.R` parsing free-text Epic CCOT
notes. Multiple assessments per encounter allowed — downstream code
slices to the first per encounter for T0.

| Column | Type | Notes |
|---|---|---|
| `pat_enc_csn` | chr | |
| `patient_id` | chr | |
| `encounter_id` | chr | |
| `first_assessment_datetime` | POSIXct | Becomes T0 for CCOT cases |
| `recommendation_text` | chr | Free text (may be NA on parse failure) |
| `recommendation_category` | chr | One of `monitor` / `escalate` / `RRT called` / `transfer` (`RECOMMENDATION_LEVELS`) |
| `note_parse_success` | lgl | Whether ETL successfully extracted required sections |

**Used by:** Overview, CCOT Outcomes, Data Quality.

---

### 3. `deterioration_fact` — structured deterioration events
**Source:** structured pediatric deterioration index pulls from Epic
Caboodle. One row per discrete event.

| Column | Type | Notes |
|---|---|---|
| `pat_enc_csn` | chr | |
| `deterioration_datetime` | POSIXct | Event timestamp |
| `event_type` | chr | e.g. `hypotension`, `hypoxia`, `altered_mentation`, `tachycardia` |
| `severity` | chr | `mild` / `moderate` / `severe` |

**Used by:** Data Quality (missingness), future outcome enrichment.
Available to all modules via `global.R`.

---

### 4. `rrt_fact` — RRT activations
**Source:** Epic RRT / Code event log. `activation_reason` is a single
free-text field; `tab_rrt_outcomes.R` buckets it with `stringr`.

| Column | Type | Notes |
|---|---|---|
| `pat_enc_csn` | chr | |
| `activation_datetime` | POSIXct | T0 for RRT cases |
| `activation_reason` | chr | Free text — bucketed in-app via `RRT_REASON_BUCKETS` |
| `disposition` | chr | e.g. `Remained on floor`, `Transferred to PICU`, `Transferred to CICU` |

**Used by:** Overview, RRT Outcomes.

---

### 5. `transfers` — ADT transfer events + emergency flags
**Source:** ADT transfer events from Clarity, joined to intubation
(procedure / medication) and vasopressor (MAR) flags at the time of
transfer. One row per transfer (typically one per encounter).

| Column | Type | Notes |
|---|---|---|
| `pat_enc_csn` | chr | |
| `transfer_datetime` | POSIXct | Used for time-to-transfer & hour-of-day |
| `intubated_at_transfer` | lgl | Component of emergency-transfer flag |
| `vasopressor_at_transfer` | lgl | Component of emergency-transfer flag |

**Used by:** all outcome tabs. Transfers occurring >72h after T0 are
excluded from outcome attribution but remain visible in raw tables.

---

### 6. `flowsheet_rows` — PEWS components
**Source:** Epic flowsheet rows (`FLO_MEAS_ID`) for the three PEWS
components. One row per component-timestamp. **Composite PEWS is
computed in R** (`global.R`) as the sum of the three components, so any
PEWS scoring change should be made there.

| Column | Type | Notes |
|---|---|---|
| `pat_enc_csn` | chr | |
| `flowsheet_datetime` | POSIXct | Component recorded-at time |
| `behavior_score` | int | 0–3 |
| `cardiovascular_score` | int | 0–3 |
| `respiratory_score` | int | 0–3 |
| `pews_total` | int | Computed = sum of the three component scores |

**Used by:** CCOT Outcomes (24h-pre-T0 trajectory), Data Quality (PEWS
completeness KPI).

---

### 7. `charges` — pro-fee billing
**Source:** professional-fee charge feed. Links by `pat_enc_csn` + date.

| Column | Type | Notes |
|---|---|---|
| `pat_enc_csn` | chr | |
| `charge_date` | Date | Used as the date column for the global filter |
| `cpt_code` | chr | CPT / E&M code |
| `cpt_descr` | chr | Human-readable code description |
| `provider` | chr | Billing provider name |
| `unit` | chr | Unit at time of service (mirror `FLOOR_UNITS`) |
| `charge_amount` | num | Dollar amount per charge line |

**Used by:** Charges & Finance, Overview (total charges KPI). The
**billing capture rate** is computed as: distinct `pat_enc_csn` with at
least one charge in range ÷ distinct CCOT encounters in range.

---

### 8. `nomad_survey` — implementation outcomes (modified NoMAD)
**Source:** REDCap export of the modified NoMAD instrument. Two
respondent tracks are presented separately on Tab 5 because their
response cadences differ: CCOT team weekly (dense longitudinal); floor
providers ad-hoc (sparse).

| Column | Type | Notes |
|---|---|---|
| `respondent_id` | chr | Pseudonymous respondent identifier |
| `survey_date` | Date | Survey wave / submission date |
| `respondent_role` | chr | `CCOT team` or `Floor provider` |
| `acceptability` | num | 1–5 |
| `appropriateness` | num | 1–5 |
| `feasibility` | num | 1–5 |
| `free_text` | chr | Optional free-text comment (may be empty) |

Subscale names must match `NOMAD_SUBSCALES` in `global.R`.

## Derived analytic frames (built in `global.R`)

You do **not** need to construct these — they are built from the
dataframes above when `global.R` is sourced. Listed here for reference.

### `ccot_cases`
- One row per encounter (first CCOT assessment only).
- Joins `ccot_assessments` + `encounters`.
- Adds `T0`, `T0_hour`, `T0_shift`, `T0_dow`.

### `ccot_outcomes`
- `ccot_cases` left-joined to `transfers`.
- Adds `hours_to_transfer`, `within_window` (≤72h), `emergency_transfer`
  (`intubated_at_transfer | vasopressor_at_transfer` AND within window),
  `transfer_hour`, `transfer_shift`.

### `rrt_cases`
- `rrt_fact` + `encounters` + `transfers`.
- Same outcome columns and time-of-day columns as `ccot_outcomes`,
  indexed on activation timestamp.

## Time-of-day analysis

Every event with a timestamp is decorated with `hour_of()` and
`shift_of()` helpers in `global.R`. The dashboard surfaces hour-of-day
explicitly in three places:

- **Overview → Patient pipeline (Sankey)** — flow from admission
  through watcher list → CCOT eval → RRT → PICU transfer →
  emergency/routine, with dropouts at each stage so you can see where
  patients exit the pipeline.
- **Overview → Hour-of-day distribution** — overlaid lines for CCOT
  notes, RRT calls, and transfers.
- **CCOT Outcomes → CCOT note hour-of-day** — stacked bars, transferred
  vs not-transferred (≤72h).
- **RRT Outcomes → RRT hour-of-day** — stacked bars, emergency-transfer
  vs non-emergent.

Shift bucket boundaries are defined once in `SHIFT_BUCKETS` (`global.R`)
— edit there to change everywhere.

## ETL: parsing CCOT notes

`etl_ccot_notes.R` is a scaffold for converting free-text Epic CCOT
notes into the `ccot_assessments` schema above. It:

1. Takes a `notes_df` with `pat_enc_csn`, `patient_id`, `encounter_id`,
   `note_id`, `note_datetime`, `note_text`.
2. Extracts **Assessment**, **Recommendation**, and **Plan** sections
   with regex (`SECTION_PATTERNS`).
3. Classifies `recommendation_text` into the four
   `RECOMMENDATION_LEVELS` using keyword buckets
   (`RECOMMENDATION_BUCKETS`).
4. Returns a tibble matching `ccot_assessments`.

Lines marked `INSTITUTION-SPECIFIC` are where your CCOT SmartPhrase /
template wording must be plugged in.

```r
source("etl_ccot_notes.R")
ccot_assessments <- run_ccot_etl(notes_df)
```

## Wiring real data — checklist

1. Replace `data/simulate_data.R` with database / REDCap pulls (DBI,
   `redcapAPI`, etc.) that produce dataframes with the schemas above.
2. Confirm timezones — every `POSIXct` should be in a single consistent
   tz (recommend `America/Chicago` or your hospital's local tz).
3. Confirm `pat_enc_csn` strings join cleanly across all sources
   (leading zeros / type mismatches are the usual culprit).
4. Verify `unit` strings in `encounters` and `charges` match
   `FLOOR_UNITS` exactly, otherwise filters drop rows silently.
5. Compute or confirm `pews_total` (`global.R` does the sum, but if your
   site uses weighted PEWS or PEWS+, override there).
6. Pass `notes_df` through `run_ccot_etl()` and inspect
   `note_parse_success` — the Data Quality tab surfaces failures for
   manual review.
